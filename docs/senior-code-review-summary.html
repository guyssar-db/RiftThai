สรุปก่อน deploy จริง

ภาพรวมโปรเจกต์ดีและใช้งานได้แล้ว แต่ควรปิดความเสี่ยงด้าน Server API และลดภาระของหน้า Design ก่อนเปิดใช้งานจริงใน production

P0 · เร่งด่วนSecurityตรวจสิทธิ์และ validate input ทุก mutation
P1 · สำคัญPerformanceลดการคำนวณซ้ำและขนาด card catalog
P2 · ปรับปรุงMaintainabilityแยกไฟล์ Svelte ขนาดใหญ่เป็น component

ภาพรวมผลรีวิว

โครงสร้างมี auth, rate limit, security headers และการ normalize data แล้ว จุดที่ต้องให้ความสำคัญคือ API ที่ใช้ service role, validation ของ payload และหน้า Design ที่โหลดข้อมูล/คำนวณจำนวนมากบน client

ข้อสรุป: แก้ P0 ให้ครบก่อน deploy, ทำ P1 ใน release เดียวกัน และเก็บ P2 เป็น refactor หลังระบบนิ่ง

Performance หน้า Design

  • สร้าง normalized search index ครั้งเดียว ไม่ normalize ทุก card ทุกครั้ง
  • เก็บ hasCollection เป็น derived value แทน Object.keys(...) ต่อ card
  • เพิ่ม decoding="async" และ responsive image
  • แยก card grid และใช้ virtualization เมื่อจำนวน card สูงขึ้น
  • โหลด card catalog แบบ lazy หรือผ่าน server API หากไม่ต้องใช้ทั้งหมดทันที

Security ของ Server Actions / API

  1. Ownership: ทุก query ต้อง filter ด้วย user_id จาก session เท่านั้น ห้ามเชื่อ user_id จาก client
  2. Validation: ตรวจ type, จำนวนรายการ, quantity สูงสุด, card code และ enum ด้วย schema เช่น Zod
  3. Admin: รวม logic เป็น requireAdmin(user) และตรวจซ้ำใน service layer
  4. CSRF: endpoint ที่ใช้ cookie และเปลี่ยนข้อมูลควรตรวจ Origin/Referer หรือใช้ CSRF token
  5. Rate limit: in-memory Map ใช้ได้แค่ single instance; production หลาย instance ควรใช้ Redis/Upstash
  6. RLS: เปิด Row Level Security ใน Supabase เป็น defense-in-depth แม้ server จะตรวจสิทธิ์แล้ว

Checklist ก่อน deploy

  • ทดสอบ User A แก้/ลบ deck ของ User B ไม่ได้
  • ทดสอบ user ปกติเรียก admin endpoint ไม่ได้
  • reject quantity ติดลบ, Infinity, string และ object
  • จำกัด batch collection ไม่เกินจำนวนที่กำหนด
  • ไม่ส่ง database error หรือ stack trace กลับ client
  • ตรวจ session หมดอายุและ banned user กับทุก mutation
  • เพิ่ม audit log สำหรับ ban, delete, update card และ admin actions
  • รัน type-check, lint, build และทดสอบบน mobile viewport
